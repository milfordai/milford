title: "Deployment"
description: "Run Loage with Docker or directly with Node."

Loage is one Node process with no database. The image is built for `linux/amd64` and `linux/arm64`, so it runs on a Raspberry Pi or a small server.

## Docker Compose

Put `loage.config.yaml` and a `flows/` directory next to `docker-compose.yml`, then set your keys:

```bash
export LOAGE_TOKEN=change-me
export ANTHROPIC_API_KEY=sk-ant-...
docker compose up --build
```

The compose file mounts `./loage.config.yaml` and `./flows` read-only under `/config` and passes these variables through: `LOAGE_TOKEN`, `ANTHROPIC_API_KEY`, `OPENAI_API_KEY`, `GROQ_API_KEY`, `TYPESAFE_API_KEY`. Add the variables your config uses to the `environment` list.

Flow file paths in the config are relative to the config file, so `./flows/triage.json` resolves to `/config/flows/triage.json`.

<Note>
  The image healthcheck calls `/health` on port 8080. If you change `server.port`, update the healthcheck.
</Note>

## MCP server image

The `Dockerfile` has a second target for the [MCP server](/guides/mcp). Set `mcp.transport: http` and `mcp.auth.tokens` in the config, then run it with the `mcp` profile:

```bash
export LOAGE_MCP_TOKEN=change-me
docker compose --profile mcp up --build mcp
```

It listens on port 8090 and its healthcheck calls `/health` there. The HTTP server image stays the default target.

## Image publishing

The `docker` GitHub Actions workflow builds multi-arch images when you push a `v*` tag. It pushes the HTTP server to `ghcr.io/<owner>/<repo>` and the MCP server to `ghcr.io/<owner>/<repo>-mcp`, each tagged with the version and `latest`. New GHCR packages start private, so make them public in the package settings if others should pull them.

## Running offline

Loage works without internet when its providers are local: a classifier behind the `http` provider, or a local OpenAI-compatible server. Use `fallback` to prefer local providers and fall back to a cloud provider.

## Without Docker

```bash
pnpm install && pnpm build
node packages/server/dist/cli.js loage.config.yaml
```

## Reliability settings

Set these before you expose the server to other clients:

- Keep `server.auth.tokens` set. Without tokens the API is open.
- Tune `run.timeoutMs`, `run.maxConcurrentRuns` and `server.maxBodyBytes` to your workload. The defaults are 60 seconds, 64 runs and 1 MB.
- Add `circuitBreaker` and a `fallback` to providers that can go down, and `rateLimit` to providers with quotas. See [providers](/providers/overview).
